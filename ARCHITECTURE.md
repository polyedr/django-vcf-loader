# Архитектура приложения

## Назначение

Приложение загружает основные данные о генотипах из VCF-файла в SQLite и
отдаёт их через REST API с фильтрацией по хромосоме и координате.

Проект поддерживает загрузку VCF от нескольких образцов. Справочные модели
описывают вид, сборку генома и хромосомы, а `Genotype` хранит данные строки
VCF и связь с образцом.

## Основные компоненты

### Django-проект `config`

Содержит общие настройки и корневую маршрутизацию:

- `config/settings.py` — Django, SQLite и подключённые приложения;
- `config/urls.py` — административный раздел и API по префиксу `/api/`;
- `config/wsgi.py` и `config/asgi.py` — точки запуска приложения.

### Приложение `genotypes`

Вся предметная логика находится в одном Django-приложении:

- `models.py` — модели и связи предметной области;
- `management/commands/load_vcf.py` — загрузка VCF;
- `serializers.py` — преобразование модели в JSON;
- `views.py` — получение и фильтрация данных;
- `urls.py` — маршрут `/api/get_genotypes/`;
- `tests.py` — тесты загрузчика и API.

Дополнительный service layer не используется: текущая логика небольшая и
хорошо помещается в management command и class-based view.

## Модель данных

Справочная часть построена следующими связями:

- `Species` содержит биологический вид;
- `Assembly` принадлежит виду;
- `Chromosome` принадлежит сборке;
- `Sample` принадлежит виду;
- `Genotype` связан с хромосомой и образцом.

Каждая строка VCF представлена одной записью `Genotype`:

- `sample` — образец из заголовка VCF или параметра команды;
- `chromosome` — связь с хромосомой из `CHROM`;
- `position` — координата из `POS`;
- `ref` — референсный аллель из `REF`;
- `alt` — альтернативный аллель или список аллелей из `ALT`;
- `gt` — генотип образца из поля `GT`.

Для частого запроса по хромосоме и координате создан составной индекс:

```text
(chromosome, position)
```

`Coordinate` и `Allele` не вынесены в отдельные таблицы. Это сохранило
простую пакетную загрузку и не добавило миллионы дополнительных строк.
Остальные колонки VCF также не сохраняются.

## Поток загрузки VCF

Команда запускается так:

```bash
python manage.py load_vcf <путь-к-файлу>
```

Последовательность обработки:

1. Проверяется существование файла.
2. Обычный VCF открывается через `open`, сжатый `.gz` — через `gzip.open`.
3. Метаданные и строки заголовка пропускаются.
4. Из `#CHROM` определяется имя образца.
5. Создаются или переиспользуются Species, Assembly, Sample и Chromosome.
6. Строки данных разбираются по символу табуляции.
7. Позиция `GT` определяется по колонке `FORMAT`.
8. Объекты `Genotype` записываются через `bulk_create` пачками по 5000.

Файл читается построчно, поэтому его полный объём не хранится в памяти.
BioPython не нужен: для используемых полей достаточно стандартного формата
VCF и модулей Python.

## Поток API-запроса

Пример:

```text
GET /api/get_genotypes/?chromosome=chr1&coordinate=783006
```

Запрос проходит через следующие компоненты:

```text
config/urls.py
    → genotypes/urls.py
    → GenotypeListView
    → Django ORM
    → SQLite
    → GenotypeSerializer
    → JSON
```

`GenotypeListView` построен на DRF `ListAPIView`. Он поддерживает независимые
фильтры `species`, `assembly`, `sample`, `chromosome` и `coordinate`.
Некорректная координата возвращает ответ HTTP 400. В JSON поле модели
`position` называется `coordinate`, как в условии задания. Связанные модели
представлены понятными именами, а не внутренними идентификаторами базы.

## Тестирование

Тесты используют отдельную временную базу Django и маленький файл
`genotypes/fixtures/tiny.vcf`.

Проверяются:

- загрузка обычного VCF;
- загрузка `.vcf.gz`;
- извлечение `GT`, в том числе не с первой позиции `FORMAT`;
- создание и переиспользование связанных моделей;
- загрузка файлов для разных образцов;
- получение всех записей;
- фильтрация по хромосоме и координате;
- пустой результат;
- ошибка при некорректной координате.

Полный файл GIAB не используется в автоматических тестах.

## Принятые ограничения

- Из VCF читается первый образец; имя можно переопределить через `--sample`.
- Повторный запуск команды для того же файла создаёт повторные записи.
- API не использует пагинацию, поскольку она не требовалась в задании.
- SQLite подходит для тестового проекта и локальной проверки, но не рассчитан
  на высокую конкурентную нагрузку.
- Настройки предназначены для локального запуска: `DEBUG=True`, встроенный
  сервер Django.

Для постоянного публичного размещения предполагается отдельная конфигурация:
`DEBUG=False`, переменные окружения, Gunicorn, Nginx и HTTPS.

## Возможное развитие

При необходимости можно добавить обработку всех sample-колонок одного VCF,
защиту от повторной загрузки файла и пагинацию API. Отдельные `Coordinate` и
`Allele` стоит вводить только при появлении запросов, которым нужна такая
нормализация.
